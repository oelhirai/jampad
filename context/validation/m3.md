# Validation Spec: M3 — Tempo & Key Detection

**App:** JamPad
**Package:** `com.jampad`
**Prerequisite:** Fresh launch, no prior session. Mic permission will be requested on first REC.

---

## Flow 1: Smoke Check — Empty State (FREE mode)

> Watch: header layout crowding, TAP button visibility, BPM "—" display

1. Launch app → expect dark theme, "JamPad" title visible
2. Verify header shows: TAP button, "—" BPM display with "BPM" subtitle, ± buttons, settings gear
3. Verify bar count chips (4/8/16) are NOT visible (FREE mode hides them)
4. Verify waveform strip shows "Record a riff to get started"
5. Verify Guitar tab is selected (amber), shows "Just hit REC and play"
6. Verify red REC button visible at bottom
7. Verify mini mixer shows Guitar/Drums/Bass sliders

---

## Flow 2: Tap-Tempo → FIXED Mode

> Watch: BPM display update, bar count chips appearing, source subtitle

1. Tap TAP button once → expect BPM still shows "—" (need ≥2 taps)
2. Tap TAP button again → expect BPM number appears with "tap" subtitle
3. Tap TAP button 2 more times → expect BPM updates to a reasonable value (~100-200 range depending on tap speed)
4. Verify bar count chips (4/8/16) are now visible (FIXED mode)
5. Verify Guitar tab message changed to "Set tempo with TAP, then REC"
6. Tap ± buttons → expect BPM changes by 1, subtitle changes to "manual"

---

## Flow 3: Free-Record + Auto-Detect

> Watch: state transitions, detection spinner, key/BPM display in guitar tab

1. Clear session (if needed) to return to EMPTY state
2. Verify mode is FREE (no bar count chips, Guitar tab says "Just hit REC and play")
3. Tap REC button → expect permission dialog (first time) → grant permission
4. Verify state changed to RECORDING — waveform shows "Recording...", button shows "STOP"
5. Wait 3-4 seconds (let mic capture ambient sound)
6. Tap STOP button → expect transition to LOOPING state
7. Verify Guitar tab briefly shows "Detecting tempo & key..." with spinner
8. After detection completes → verify Guitar tab shows detected key (e.g., "Key: C Major") and BPM with "(detected)" label
9. Verify BPM display in header updated from "—" to a number with "detected" subtitle
10. Verify waveform shows beat markers (beatCount > 0)
11. Verify button now shows "OVERDUB"

---

## Flow 4: Key Override

> Watch: dropdown menu rendering, key update propagation

1. From Flow 3 looping state, ensure Guitar tab is selected
2. Verify detected key is displayed with edit icon
3. Tap the key display → expect dropdown menu opens with all 12 keys (C through B)
4. Select a different key (e.g., "A") → expect dropdown closes
5. Verify key display updates to show the selected key
6. Switch to Bass tab → verify bass key selector shows the overridden key

---

## Flow 5: Manual BPM Adjustment After Detection

> Watch: BPM label update, source subtitle change, drums/bass resync

1. From looping state, note the current detected BPM
2. Tap "+" button in header → expect BPM increases by 1
3. Verify subtitle changes from "detected" to "manual"
4. Tap "−" button → expect BPM decreases by 1
5. Verify drums/bass (if enabled) continue playing (no crash or silence)

---

## Flow 6: Clear Session Reset

> Watch: all state resets to defaults

1. From looping state, tap the delete/clear button (left of big button)
2. Verify state returns to EMPTY:
   - Waveform shows "Record a riff to get started"
   - Guitar tab shows "Just hit REC and play" (back to FREE mode)
   - BPM shows "—" with "BPM" subtitle (NONE source)
   - Bar count chips hidden (FREE mode)
   - REC button visible (red circle icon)
   - No detected key shown

---

## Flow 7: Overdub After Detection

> Watch: overdub works correctly after free-record detection

1. Complete a free-record cycle (REC → STOP → detection completes)
2. Tap OVERDUB button → verify state changes to OVERDUBBING
3. Verify waveform border changes to amber
4. Verify button shows "STOP"
5. Wait 2 seconds, tap STOP → verify returns to LOOPING
6. Verify BPM and key display remain unchanged

---

## Flow 8: Tab Navigation During Looping

> Watch: all three tabs render correctly during playback

1. From looping state with detected key/BPM
2. Tap Drums tab → verify sequencer/pads UI renders, tab highlighted cyan
3. Tap Bass tab → verify bass controls render, tab highlighted purple
4. Tap Guitar tab → verify detection info (key + BPM) still displayed, tab highlighted amber

---

## Visual Audit Checklist

- [ ] Header: TAP button readable, BPM display aligned, no text clipping
- [ ] Header: bar count chips appear/disappear cleanly when mode changes
- [ ] Waveform: beat markers visible when BPM is detected, absent when NONE
- [ ] Guitar tab: detection spinner centered, key/BPM info well-spaced
- [ ] Guitar tab: key dropdown renders without clipping or overflow
- [ ] Big button: correct color per state (red=REC/STOP-recording, blue=OVERDUB, amber=STOP-overdub)
- [ ] Clear button: only visible when loop exists
- [ ] Overall: dark theme consistent, no white flashes or unstyled elements
